The actual workflow, step by step
1
You build in Claude
Design, write, and iterate on HTML files here. Download the finished file to your Mac Mini.
2
Commit to GitHub
Drop the file into your pulse-build repo and push. GitHub Pages immediately gives it a live URL like yourname.github.io/pulse-build/checklist.html.
3
Share the URL with your partner
Text or email him the link. He opens it in any browser on any device. No installs, no accounts, no friction.
4
He gives feedback
For quick reactions: text or voice note. For tracked feedback: a GitHub Issue on the repo. For doc edits: comments in Google Docs.
5
You bring feedback back to Claude
Paste his notes into this conversation, or into your Obsidian note for the next session. Iterate and repeat.
6
Weekly video sync
Walk through what's live on GitHub Pages together. Align on what to build next. Keep the loop short.
Honest limitations to know upfront
Claude can't collaborate directly with your partner. He doesn't have access to this project, and you wouldn't want to give it to him — this is your build environment. He interacts with outputs, not the process.
GitHub requires minimal setup from you. One repo, GitHub Pages turned on (Settings → Pages → Deploy from main). Takes 10 minutes. After that, every file you push is automatically live.
HTML files are self-contained but not a live app yet. Right now everything we build is a prototype — it looks and feels like an app but doesn't have a real backend. That's fine for this phase. When you're ready to deploy a real app, that's a Supabase + hosting conversation.
Obsidian doesn't sync to Claude automatically. You have to manually paste or upload notes from Obsidian when they're relevant. Keep a running session-notes.md in your project folder and paste the relevant bits at the start of each session.
