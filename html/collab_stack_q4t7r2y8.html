The workflow, every time
1
Build in Claude
Design and iterate on HTML files here. Download the finished file with Cmd+S directly to /Users/payton/pulse-build/html/
2
Push to GitHub
Three commands every time:

git add .
git commit -m "description"
git push
3
Share the URL
Text or email the link: metroplusdsm-lab.github.io/pulse-build/html/filename.html
4
Collect feedback
Partner texts reactions, or files a GitHub Issue. You bring feedback back to Claude as context for the next session.
5
Weekly sync call
Walk through what's live. Align on what to build next. Keep the loop short and regular.
Honest limitations
Claude can't collaborate with your partner directly. He doesn't have access to this project. He interacts with outputs — URLs — not the build process.
HTML files are prototypes, not a live app yet. Everything looks and feels like an app but has no backend. That's right for this phase. When you're ready for a real backend, that's a Supabase conversation.
Obsidian doesn't sync to Claude automatically. Keep a running session note and paste the relevant bits at the start of each Claude session to maintain continuity.
File names matter for URLs. No spaces, dashes only. partner-checklist.html not Partner Checklist.html. Save with the right name when Cmd+S dialog opens.
